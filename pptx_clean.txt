Core Feature 1 â€” Secure QR Authentication
SECURE QR
AUTHENTICATION
HMAC-SHA256
Token Signing
Each QR is dynamically signed
and tied to one physical copy.
Forged or reused codes are
rejected before any transaction.
Authentication Workflow
A registered user presents their QR code â†’ system validates via HMAC-SHA256 â†’ session binding â†’ access is granted only after verification clears.
Transaction Traceability
Each scan ties back to a specific registered account and a specific book copy (CopyBookID schema). Every transaction is logged with user ID, book ID, date/time, due date, and status.
Anti-Duplication
Idempotency keys prevent duplicate submissions for borrow, return, and reservation actions â€” addressed at implementation level, not through procedural workarounds.
Security Design Principle
QR codes function as dynamic verification tokens, not static identifiers. One-time code generation, session binding, and server-side validation prevent forgery and replay attacks.
